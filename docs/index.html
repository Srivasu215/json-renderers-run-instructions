The Origin Tale

From Monolithic Tangle to Architectural Elegance

Once upon a time in front-end development, every component builder was monolithic. If you wanted to build a table, your table engine had to iterate arrays, stamp HTML headers, build nested cell matrices, and inject them into the browser DOM all in one messy loop.

When teams wanted to reuse that declarative power for cards, accordions, dynamic select inputs, or master-detail dashboards, they hit a brick wall: the logic was inextricably bound to the DOM and table structures.

The Breakthrough: What if an instruction runner knew absolutely nothing about HTML, CSS, or tables? What if it acted as a pure mathematical blackboard transformer operating on an in-memory Shared Registry? That became json-renderers-run-instructions.

How Simple It Is

Execute Instructions in 3 Lines of Code

Import runInstructions directly from CDN or npm. Define your registry target and let the runner populate the specification tree synchronously in-place. 

import { runInstructions } from "https://keshavsoft.github.io/json-renderers-run-instructions/dist/min.js";

// 1. Prepare registry blackboard
const registry = {
    data: {
        columns: [{ key: "id", title: "ID" }, { key: "name", title: "Product" }],
        data: [{ id: 101, name: "Mechanical Keyboard" }]
    },
    base: { tagName: "div", children: [] }
};

// 2. Run instructions
runInstructions({
    single: [/* 1D header transformations */],
    double: [/* 2D row x column matrix */],
    registry
});

// Result: registry.base is now ready for rendering!

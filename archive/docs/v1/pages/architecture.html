Technical Blueprint

Runtime Architecture Deep-Dive

How the Shared Registry model and deterministic 1D / 2D instruction pipelines achieve lightning-fast, zero-DOM spec building.

Core Primitive

The Shared Registry Pattern

Instead of piping complex state through multi-stage intermediate functional pipelines, json-renderers-run-instructions uses a centralized, in-memory blackboard called the Registry.

registry.data
Source Collections

Holds input arrays: columns, rows, filter sets, options, or domain models.

registry.base
Target Specification Tree

The JSON specification node mutated in-place by single and double instruction loops.

Deterministic In-Place Mutation Pipeline → 0 Memory Duplication
Why In-Place Registry Mutation?
  1. Microsecond Speed & Low GC: Rendering 1,000 rows × 20 columns involves 20,000 nodes. Immutably cloning whole JSON trees on every iteration triggers severe memory spikes and Garbage Collector stutter. In-place mutation executes in single-digit milliseconds.
  2. Zero Side Effects: Because the runner does not touch the browser DOM or window objects, execution is completely free of DOM-triggered reflows or layout thrashing.
  3. Full Debugging Inspectability: Setting showLog: true instantly snapshots the blackboard state at each step for unmatched developer observability.
Execution Phases

Phase 1 (1D) vs Phase 2 (2D) Execution

Execution proceeds in two strictly synchronous, predictable phases:

Phase 1
Single Instructions (1D)

Powered by json-instruction-single. Traverses 1D linear collections.

  • Maps registry.data.columns into table header elements (<th>).
  • Generates column width rules (<colgroup> & <col>).
  • Transforms options lists for dropdowns and datalists.
Phase 2
Double Instructions (2D)

Powered by json-instruction-double. Computes Cartesian matrices.

  • Iterates data rows × column definitions.
  • Calculates individual cell values, styles, and data attributes.
  • Mounts structured matrix children under registry.base.
// Typical execution signature
runInstructions({
    single: [
        {
            source: "data.columns",
            template: "headers.default",
            target: "base.children[0].children[0].children"
        }
    ],
    double: [
        {
            outerSource: "data.data",
            innerSource: "data.columns",
            template: "cells.default",
            target: "base.children[1].children"
        }
    ],
    registry,
    showLog: false
});
